# 言语理解墨墨制卡方法与流程

## 目标

把课程材料或用户提供的词语，转化为能够帮助理解词义、辨析近义词并迁移到新题的长期学习卡。数量、字段和技术复杂度都不能替代学习效果。

## 用户需要提供什么

首次使用只需提供：

1. 课程原材料或需要整理的词语；
2. 目标墨墨卡组与章节；
3. 是否只生成预览，还是在最终确认后发布。

用户不需要编写脚本、整理 JSON 或处理中间审查文件。系统只在发布前要求一次最终授权。

## 九步流程

1. **来源清点**：合并同一课程的文档、音视频和逐字稿版本，记录每条证据的位置。
2. **词义审查**：为每个“词面＋义项”确定准确词义、特别之处、识别线索、判断维度和误用边界。
3. **近义辨析**：重建完整成员关系；逐词说明含义和落点，并建立能够连接全部成员的最小差别。
4. **场景应用**：只为存在稳定考点的内容出题。题干必须是具体语境，不能是定义换成问句；答案必须唯一，并逐项排除干扰项。
5. **学习预览**：按基本词义、近义辨析、场景应用分别展示，先供阅读，不写入墨墨。
6. **冻结成果**：固定标题、正文、顺序、引用和内容哈希；冻结后写入器无权润色或补写。
7. **生成发布清单**：对照目标章节当前快照，逐卡决定创建、更新或保持不变，并固定动作数量和发布哈希。
8. **GitHub最终授权**：授权必须与精确发布哈希、章节和动作数量绑定；聊天同意和本地令牌不能替代。
9. **写入与全量回读**：按冻结内容原样写入；超时先回读再决定是否重试；最后核对全部标题、正文、引用、章节数量和计划外增量。

## 三类卡片标准

### 基本词义

第一层固定为“词义 → 特别之处 → 做题识别点 → 一眼辨析”。只有确实有训练价值时，才增加判断维度、误用边界和典型语境。

### 近义辨析

必须直接写出每个词，禁止用“前者、后者、两者”等模糊指代。每条最小差别都要说明题干中应观察什么；证据不足时明确标记待核，不能编造差别。

### 场景应用

题干必须包含具体主体、条件、动作或结果。审查时隐藏标准答案重新判断；只要两个选项仍可成立，就不允许冻结。卡片背面必须包含线索提取、适配理由、逐项排除和迁移规则。

## 三种使用方式

- **只审查**：检查现有卡片的重复、冲突、缺失和错误引用，不生成写入计划。
- **生成预览**：完成语义和应用审查，输出三类卡片预览，但停在冻结前。
- **受保护发布**：在预览通过后生成发布清单，经 GitHub 最终授权再写入并回读。

## 立即停止的情况

- 来源或义项仍不明确；
- 辨析只是重复定义；
- 应用题只是定义改写，或存在多个可选答案；
- 目标章节、动作数量或内容在授权后发生变化；
- 写入结果不确定但尚未回读；
- 最终回读与冻结成果不一致。

## 在 Codex 中怎么说

可以直接输入：

> 使用 verbal-maimemo-cards，读取我提供的课程材料，先完成来源、词义、辨析和应用审查，只生成三章节预览，不写入墨墨。

需要发布时再输入：

> 使用已经审定的冻结成果生成发布清单；先给我动作数量和发布哈希，未经 GitHub 最终授权不要写入。

这套方法适用于任意规模的词汇项目，具体词数和卡片数量不属于流程定义。
