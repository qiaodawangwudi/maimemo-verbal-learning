# 言语墨墨制卡

## 核心原则

把每批材料接入可追溯、可复核、可安全发布的正式词汇库。最高标准是学习效果：学习者先用关键词式核心辨析抓住选词落点，再理解完整词义、识别题干线索并迁移到新语境。

严格执行：

`来源清点 -> 语义档案 -> 全库重复对账 -> 辨析审查 -> 应用审查 -> 冻结卡片 -> 发布清单 -> GitHub授权 -> 写入 -> 全量回读`

每一步必须产出有效工件，后一步不得代替前一步。字段齐全不等于语义合格，聊天批准不等于发布授权，写入成功响应不等于发布完成。任一工件缺失、失效或相互不一致时，停止并报告工件名、失败条件和恢复入口。

## 人机分工与批量审查

用户只负责确定材料、学习目标、目标卡库和最终抽样验收，不承担逐词审核。逐词质量责任不能转嫁给用户，也不能因为用户不逐词确认就降低标准。

- 程序只可自动完成来源清点、证据定位、规范化、哈希、渲染和确定性校验；不得用统一模板批量撰写或批准词义、核心辨析、闭组结论、多维判断、应用场景和干扰项理由。
- 内容拟写与质量复核必须分成两个阶段。复核阶段先隐藏拟写结论，按来源和相邻词独立回答“是什么意思、区别在哪里、什么条件决定选择”，再与候选卡逐项比对；不得由同一生成步骤填写 `approved`、闭组理由或维度不足理由。
- 没有逐词人工复核时，必须执行上述来源优先的第二遍复核并留下绑定原字段哈希的审查工件；它不冒充用户人工审核，也不冒充独立第三方审核。受保护发布仍须通过 GitHub 质量门槛。
- 一次预览必须覆盖本批全部已审义项：每个义项均有基础卡、一眼辨析和场景应用；无法可靠完成的义项保持 `pending` 并列入缺口清单，不能用“已审子集”掩盖整批缺失。
- 批量质量门槛按整批统计：固定闭组理由、固定维度轴与理由骨架、少数干扰项解释轮换、`怎么选` 复述全部核心槽、套话边界或生成残片占多数时，整批失败。随机换词、换标点或打乱顺序不能视为内容独立。

## 十阶段硬门槛

| 阶段 | 必须得到 | 停止条件 |
|---|---|---|
| 来源清点 | `source_inventory` | 来源未穷尽、版本未合并、证据定位缺失或来源权限不明 |
| 语义档案 | `semantic_registry` | 新证据未进入义项判断；存在 `pending` / `conflict` |
| 全库重复对账 | `library_reconciliation` | 未绑定完整快照；同词多卡、一词多义或异形词仍待决；新建缺少零候选证明 |
| 辨析审查 | `discrimination_review` | 比较组未按完整成员和义项重建；最小差别不成立 |
| 应用审查 | `application_review` | 两个或更多选项仍成立；只有非空说明而无唯一性证据 |
| 冻结卡片 | `frozen_cards` | 内容仍可变；卡片哈希、词序或引用目标未固定 |
| 发布清单 | `release_manifest` | 章节、动作、全库快照或冻结卡片哈希不一致 |
| GitHub授权 | `github_authorization` | 最终授权失败、过期、范围不符或发布哈希不符 |
| 写入 | `write_receipts` | 写入器试图改写/补全内容；请求结果不确定或数量异常 |
| 全量回读 | `readback_report` | 标题、内容、根引用、章节数量或未计划增量不匹配 |

## 不可协商的发布不变量

- 同标题只是检索线索。出现新证据时必须重开该义项的语义判断，不能为省时标为 `unchanged`。
- 比较组身份由规范成员、义项和完整关系共同决定。仅有成员重叠不得复用旧 `root_id`；先重建整组并审查全部相关卡。
- 结构校验只能证明字段存在。语义档案、辨析审查和应用审查全部通过后才能冻结。
- 授权必须绑定准确章节集合、动作总数、全库快照哈希和发布哈希。用户把一章改成三章即范围变化；发布哈希变化后旧授权失效。
- GitHub 最终授权是唯一发布授权。最终授权失败即停止；不得存在本地备用写入路径，聊天批准、环境令牌和已投入时间都不能替代它。
- `POST` 超时属于结果不确定，不属于失败。先按幂等键和全量回读确认结果；确认未写入后才可重试同一冻结请求。
- `uniqueness_rationale` 非空只证明字段存在。若两个选项都成立，应用审查失败，不能接受或发布。
- 写入器只消费冻结清单并原样传输；写入器不得生成内容，不得润色、补字段、改标题、换引用或重排卡片。

## 制卡与对账

1. 把老师原话或用户指定来源绑定到可定位证据；现有卡片只作去重和历史参照，不反向证明词义。
2. 按 `规范词面 + 义项` 对账本批与完整全库快照。`library_reconciliation` 必须绑定快照哈希和语义档案哈希；快照变化即失效。
3. 旧卡没有可核 `sense_id` 时，即使同词且只有一张也只是候选；必须确认属于同一义项后才复用并更新。同词不同义项不得覆盖旧义项。
4. 全半角、空格和大小写等机械形式差异自动归并；真正别名、繁简异体或旧称必须先作为 `aliases` 进入已审语义档案，不能靠标题猜测。
5. 同词存在多张旧卡时选择一张主卡，合并有价值内容并迁移引用；其余卡只列为待停用，不自动删除。无法确定时标记 `manual_review` 并阻止发布。
6. `create` 只有在完整快照中不存在规范词面或已审别名候选、可复用主卡和未解决重复项时才成立。标题不同不是无重复证明。
7. 新证据即使结论不变，也记录审查结果和证据增量；近义组有任何成员、义项、边界或最小差别变化时，重算整组并同步基础卡与辨析卡。
8. 基础卡主体按 `核心辨析 -> 词义 -> 一眼辨析 -> 多维判断` 组织，再按信息增量保留易错边界和典型语境。核心辨析用两至四个关键词槽，以 ` + ` 连接，直接写清条件、对象、动作或结果，例如 `近水楼台：接近某人/某事 + 优先获得利益或机会`、`投鼠忌器：顾虑伤及关联对象 + 不敢行动或放弃行动`。题干线索只能在主体之后以 `附加｜题干可圈出` 出现，不得替代核心辨析、完整词义、一眼辨析或多维判断。
9. 基础卡和辨析卡都保留 `一眼辨析` 与 `多维判断` 的方法。`一眼辨析` 只写具体词对的最短差别，如 `攻克 × 畅通：突破解决 vs 保持顺畅`，不得把整组总括句复制到每条词对。`多维判断` 只有在至少两个彼此独立、核心辨析尚未覆盖且会改变选词的维度同时成立时才显示；可用维度包括对象、程度、过程/结果、褒贬、搭配和语境排除等。`选择落点`、`核心辨析`、`词义`、`题干关键词`、`一眼辨析`、`怎么选` 都不是维度名，单个轴也不得冠名为“多维判断”。不足两个真实维度时整栏省略，绝不补造内容；但已经审定的词对材料明确提供两个以上新增判断轴而成品多维判断整批为零时，质量审查必须失败，不能用“按需省略”掩盖生成遗漏。
10. 多维判断必须先形成独立维度审查工件，再由生成器消费；生成器不得自行补轴。每个近义组都必须明确记为 `approved_dimensions` 或 `insufficient_dimensions`：前者逐轴绑定各成员判断、原始证据摘录及“改变该条件会改变选词”的检验，后者记录已检查的候选轴和不足原因。缺少任一组的处置、把全部组一律判为不足、固定轴组合配固定句式占据多数，均按“维度高度同质化”或“全部删除”失败；重复出现“对象”等合法轴名本身不算失败，只有判断骨架和证据也机械重复时才失败。
11. 同一卡片中，一个判断只出现一次。题干关键词必须是题干可观察线索，不得换句话重复核心辨析；易错边界只在提供新的排除条件时保留。辨析卡按 `核心辨析 -> 词义 -> 一眼辨析 -> 多维判断 -> 怎么选` 组织；不得用一眼辨析、多维判断或怎么选改写并重复逐词核心。
12. 应用题必须只有一个由证据支持的最佳选项，并逐一说明其他选项为何不成立。
13. 按语义档案固定词序和组内顺序；禁止直接遍历无序集合。先冻结卡片，再由同一冻结载荷生成发布清单、发布哈希和授权请求。
14. 语义候选不得因字段完整就标为已审。只有逐词完成词义、核心辨析、使用边界、做题落点和可定位证据复核的记录才可标为 `approved`；其余保留候选内容并标为 `pending`，预览和发布都必须排除。允许生成“已审子集预览”，但必须同时给出待审数量和清单，不得把子集伪称整批完成。
15. 课程位置相邻、同一讲次、同一旧 `group_key` 或单向提到另一个词，都不能建立正式近义组。正式组至少要求每个成员义项已审、边界能双向指认、每条差异绑定具体词名和可定位观察；出现第三方词义混入或组边界不闭合时，候选组必须退回重建。
16. 比较组通过标签不能由比较组生成器自行填写。生成器只能提出候选组；独立闭组审查必须逐项记录真实混淆原因、为什么成员边界已经闭合、所审成员及关系类型。仅把双向易错边界自动拼成 `reciprocal_reviewed_boundary`，不构成审查证据。
17. 场景应用必须写成可直接作答的自然事件，不得出现“题干先写到”“又明确出现”“题干没有说”“材料呈现出”等出题说明或定义复述。场景要素必须记录真实事件、限制和实际结果，不得把“所缺词语”当事件，也不得把“横线所在句准确成立”当结果。选项只放真正需要辨析的 2—4 个词；双词组可以只给两个相关选项，禁止为凑四项塞入不相干词。解析只保留决定答案的落点和真实误选项的排除条件，避免重复整段词义。
18. 应用题必须检查把每个选项实际代入后的可用性。若固定后缀、词性或词形已经直接锁定答案，而题干没有独立的语义判断价值，按“语法或词形直接泄露答案”失败。干扰项必须指出本题缺少或相反的具体条件；统一干扰项解释模板（例如批量使用“适用于……与本题情形不符”）占据多数时整批失败。
19. 用户不需要逐词验收。交付时给出完整数量、失败项清单、批量重复统计和少量代表性样卡供用户抽查；任何未通过逐词审查的记录都留在 `pending`，不得要求用户靠逐张阅读替系统兜底。

## 单一写入路径

只允许状态机中的 GitHub 受保护发布路径。写入前再次核对 `github_authorization.release_hash == release_manifest.release_hash`，且章节集合、动作总数一致。写入器必须接收冻结载荷、幂等键和发布哈希；缺少任一项即拒绝启动。

请求超时、连接中断或响应不可解析时，标记 `write_indeterminate`，停止新的创建请求。先全量回读并按幂等键、标题和内容哈希查找；只有可证明目标不存在，才重放完全相同的冻结请求。不得用新请求 ID 绕过重复检测。

所有审查、冻结、授权、写入和回读程序均随 Skill 安装在 `scripts/runtime/`。不得以“当前工作区没有项目仓库”为由改用临时脚本；通过 `scripts/run_pipeline.py` 调用内置运行时。首次使用必须先执行 `self-check`，失败时停止，不重写或猜测缺失程序。

## 示例：新证据与范围变化

输入新增了同标题词条证据，且目标从章节 A 改为章节 A/B/C：

1. 将新证据加入 `source_inventory`，重开对应 `semantic_registry` 记录。
2. 重建受影响比较组；未确认组身份前不复用 `root_id`。
3. 重新完成辨析和应用审查，冻结新卡片并生成新发布哈希。
4. 将旧 `github_authorization` 标为失效，申请绑定 A/B/C 与新发布哈希的最终授权。
5. 授权未到达前停止在 `awaiting_github_authorization`，不调用任何本地写入路径。

## 合理化反制

| 借口 | 现实 |
|---|---|
| “标题没变，先不动” | 标题不是证据身份；新证据必须进入语义审查。 |
| “旧组有重叠，复用根 ID 更稳” | 重叠不等于同一比较组；错误根引用会污染整组。 |
| “字段都填了，语义以后补” | 完整格式可能承载错误结论；审查必须先于冻结。 |
| “只多两个章节，旧批准够用” | 章节是授权范围；范围变化必然产生新发布哈希。 |
| “聊天已批准，本地令牌只是执行” | 聊天批准不是 GitHub 最终授权，本地令牌是被禁止的旁路。 |
| “超时就再发一次，最多重复” | 不确定写入必须先回读；重复不是可接受代价。 |
| “唯一性说明写了就算通过” | 字段存在不证明只有一个答案；两个选项成立即失败。 |
| “换个栏目名就不算重复” | 重复按判断内容而不是字段名判定；核心辨析、题干关键词、边界和怎么选不能改写同一句话互相填充。 |
| “为避免重复，直接删掉一眼辨析和多维判断” | 栏目必须保留在方法中；应删除重复句，只输出有独立学习价值的词对差别和判断维度。 |
| “有一个选择落点也算多维判断” | 一个轴不是多维；选择落点属于核心辨析或怎么选，不能充当维度。至少两个独立新增轴才显示整栏。 |
| “用户不逐词看，只能先批量生成” | 用户不逐词审核不等于允许机器自审；必须分离拟写与来源优先复核，并由批量门槛拦截机械骨架。 |

## Red Flags：立即停止

- 用“省时间、窗口将关、负责人承担风险、已经投入很多”替代工件验证。
- 依据标题相同判定 `unchanged`。
- 没有生成并通过全库重复对账就创建或更新基础卡。
- 用不同标题、空格、全半角或别名绕过重复检查。
- 发现多张旧重复卡后任意选最后一张，或让程序自动删除其余卡。
- 对重叠比较组直接复用 `root_id`。
- 在语义、辨析或应用审查前写入。
- 章节、动作或冻结内容变化后沿用旧授权。
- GitHub 授权失败后寻找本地令牌、备用脚本或其他接口。
- 对结果不确定的创建请求立即重试。
- 以非空字段代替内容成立性审查。
- 在基础卡重复整组辨析，或把同一句总括按每条词对重复输出。
- 因局部内容重复而从方法中删除一眼辨析或多维判断。
- 用“选择落点”填充维度，或给单个轴冠以“多维判断”。
- 用完整句、套话或“具体语义落点”代替关键词式核心辨析。
- 由候选组生成器自行声明比较组已经独立审查。
- 用占位文字充当场景事件或结果，或批量复制统一干扰项解释模板。
- 用自动循环、字段拼接、同义替换或少量句式轮换批量撰写语义判断，并让同一步骤自行标记通过。
- 让固定后缀、词性或词形直接泄露应用题答案。
- 让写入器修改冻结内容。

## 常见错误

- 只审本批而不审全库：重新冻结完整正式章节快照。
- 把旧卡或机器输出当语义证据：降级为历史线索并回到来源。
- 用 `mkjc_` 记录 ID 建引用：回读并使用稳定的 `mkjr_` 根 ID。
- 只回读刚写入的卡：执行全量回读，核对章节总数与未计划增量。
- 把“没有报错”报告为完成：只有 `readback_report.status == passed` 才能完成。
